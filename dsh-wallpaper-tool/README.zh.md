# Wallpaper Studio 壁纸工作室

给 DeepSeek Harness Web 界面铺一张自己的壁纸：上传图片或视频，调节不透明度、模糊、暗化，叠加动态特效，让侧边栏 / 内容区 / 输入框一起透出壁纸，还能轮播和手动裁切构图。

> English version: [README.md](README.md)

---

## 功能

| 需求 | 实现 |
| --- | --- |
| 自定义背景 | 「壁纸库」里的任意图片 / 视频 / 特效都能一键设为背景 |
| 上传图片和视频 | 拖拽、文件选择、多选；视频自动静音循环播放并抓取首帧做缩略图 |
| 不透明度 / 模糊 / 暗化 | 三个主滑块，另有亮度、饱和度、暗角、缩放、水平 / 垂直构图 |
| 动态背景特效 | 极光、星河流转、浮光粒子、层叠波浪、光束、细雨（Canvas 实时绘制），可当作背景，也可叠在当前壁纸之上 |
| 侧边栏 / 内容区 / 输入框透出壁纸 | 分别控制四个面板（含菜单弹层）的「面板不透明度」与「背后模糊」，直接改写界面自身的表面色令牌，明暗主题都保留各自色调 |
| 背景轮播 | 间隔、顺序（顺序 / 随机）、过渡（淡入 / 缩放 / 平移 / 模糊）、时长、参与成员可勾选 |
| 手动裁切构图 | 拖拽移动、滚轮缩放、滑块微调、旋转、多种画幅比例；图片会烘焙成新的裁切副本，视频保存取景参数 |
| 额外 | Alt+B 一键开关壁纸、缓慢动效（推拉 / 漂移 / 呼吸）、跟随系统「减少动态效果」、后台暂停动画、侧边栏快捷面板 |

## 支持的格式与平台

**平台**：桌面端（Electron 窗口）与浏览器访问的是同一套 Web 界面、同一套客户端插件机制——插件只用 DOM / CSS / Canvas / IndexedDB，所以桌面端完全可用（本机运行的正是 `desktop` profile 的桌面应用）。只有窗口最顶部的原生标题栏由应用自身绘制，壁纸不会盖住它。

**图片**（按文件类型或扩展名识别）：PNG、JPEG/JPG、WebP、GIF（含动图）、AVIF、BMP、SVG。

**视频**：MP4 / M4V（H.264+AAC；Chromium 也支持 MP4 内的 VP9 / AV1）、WebM（VP8 / VP9 / AV1 + Opus / Vorbis）、Ogg（Theora）、MOV（仅当它实际是受支持的编码，例如 H.264）。

**不能解码的会被明确拒绝**：MKV、H.265/HEVC、WMV / AVI / FLV、MPEG-2、ProRes 等——Chromium 没有对应的解封装器或解码器，插件会弹提示让你先转成 MP4(H.264) 或 WebM，而不是塞进库里变成一块黑屏。单个文件上限 320 MB。

图片格式解码由 Chromium 决定；若某张图能选中但显示不出来，通常是编码异常（例如 CMYK JPEG），转存一次即可。

## 视频声音

可以。**设置 → 背景壁纸 → 高级**里有「播放视频声音」开关和「视频音量」滑块（默认静音、默认 60%）。打开后壁纸视频会解除静音并按滑块音量播放；一旦你调整音量滑块，声音开关会自动打开。

浏览器有自动播放策略：没有用户交互时带声音的自动播放可能被拒绝。这种情况下插件会自动退回静音，并在界面上提示一次——在页面里点一下，再打开音量即可。

## 安装

这个包是标准的 DSH bundle，推荐让 Harness 里的智能体来装（它会调用 `plugin_manager install_bundle`，自动完成 package 安装与 bundle 注册）：

1. 把 `dsh-wallpaper-studio` 整个文件夹放到一个你喜欢的位置（例如桌面）。
2. 在任意 DSH 会话里说：**「把 `<文件夹绝对路径>` 安装到当前 profile」**。
3. 安装完成后刷新页面（或按提示重启），打开 **设置 → 背景壁纸**。

手动安装（仅供参考，DSH 官方建议交给 `plugin_manager` 处理）：在 profile 目录 `pnpm add file:<文件夹>`，把包名加进 `package.json` 的 `dsh.profile.bundles`，并让它加载本包的 `cordis.patch.yml`。

### 更新已安装的版本

命令行等价做法（本机已用这条流程装过一次）：

```powershell
dsh plugin --profile desktop remove dsh-wallpaper-studio
dsh plugin --profile desktop add file:C:/Users/好好福/Desktop/dsh-wallpaper-studio
```

⚠️ 对**同一个本地路径重复执行 `add`**（不先 remove）会让插件管理器的 `reconcile()` 把 `dsh.profile.bundles` 里的这一项删掉：它只保留"本次安装动作真正改动过"的包。装完请用 `dsh plugin --profile desktop` 之外的任何方式确认 `package.json` 里 `dsh.profile.bundles` 仍包含 `dsh-wallpaper-studio`；`tests/verify-install.cjs` 也会检查这一点（把 profile 路径改成你的即可）。改完 profile 后需要**完全退出并重新打开** Harness 才会加载新 bundle。

## 使用

- **设置页**：左下角「设置」→ 左侧导航里的 **背景壁纸**，共六个标签页：壁纸库 / 外观调节 / 动态特效 / 背景轮播 / 界面透出 / 高级。
- **快捷面板**：侧边栏底部「设置」上方多了一个 🖼 按钮，点开即可开关壁纸、切换下一张、叠加特效。
- **快捷键**：`Alt+B` 开关壁纸。
- 第一次上传壁纸后背景会自动开启；关闭开关不会丢设置。

## 数据与隐私

所有东西都留在本机浏览器里：壁纸原图 / 视频以 Blob 形式存进页面所在源的 IndexedDB（`dsh-wallpaper-studio`），设置以 JSON 存在同一个库；没有网络请求，不写入磁盘文件，不经过 Host。清除设置页「高级 → 清除全部壁纸与设置」即可全部删除。

若 IndexedDB 不可用（隐私窗口等），插件会自动退化为「本次会话有效」模式并如实标注。

## 实现要点

- **面板透出**：界面自身的表面色来自设计令牌——`--dsw-alias-bg-base`（窗口框架 / 文档 / 对话区）、`--dsw-specific-sidebar-fill`（侧边栏列，**注意它同时被整个窗口框架使用**）、`--dsw-specific-input-major`（输入卡片）、`--dsw-specific-menu` / `--dsw-menu-surface-fill`（菜单弹层）。内容区与输入框、菜单在 `body` 上以 `!important` 覆盖同名令牌，换成「当前调色板同色 + 用户设定透明度」；原始颜色由探针元素实时解析，浅色 / 深色主题与主题切换都不会串色。**侧边栏不这样做**：它的令牌同时画在整窗框架上，直接覆盖会连带改掉整个界面，所以插件只把该令牌设为 `transparent`（这正是让壁纸在框架后面透出来的关键），侧边栏自己的那层颜色由插件图层上的矩形绘制，只覆盖侧边栏区域。
- **菜单与弹层**：菜单是「打开才挂载」的，量到的矩形下一秒就失效，所以菜单的模糊不是画矩形，而是覆盖 `--dsw-menu-backdrop-filter`（菜单材质自己读的令牌），填充则覆盖上面两个菜单色令牌。
- **面板模糊（v1.0.1 重做）**：模糊**不施加在面板元素上**。`backdrop-filter` 会让元素成为其 `position: fixed` 子元素的包含块，桌面标题栏布局里的品牌行、输入框的浮动控件都会因此位移——这正是 v1.0.0 中「开了壁纸界面就错位」的原因。现在插件只**测量**面板几何（`elementsFromPoint` + 令牌配色确认），再在自己的图层里画出对应位置的霜面矩形；宿主元素一个样式都不改，并有专门的不变量断言守护这条线。
- **背景层**：一个 `position: fixed; z-index: -1` 的图层挂在 `body` 下，含两张幻灯片（交叉淡入淡出）、特效画布、暗化与暗角遮罩，以及上一条说的霜面矩形；`pointer-events: none`，不干扰任何交互。
- **裁切一致性**：背景层、裁切预览、烘焙出的图片三者共用同一套 `layout()` 几何计算，所见即所得。
- **性能**：一个 requestAnimationFrame 循环、DPR 上限 1.5、粒子数量随画布面积缩放、窗口隐藏即暂停、尊重 `prefers-reduced-motion`。

## 构建与测试

需要 Node ≥ 22.18（内置 TypeScript 类型擦除），本机为 Node 24：

```powershell
node build.mjs          # 生成 client.js 与 index.js，并跑一遍打包器自检
node build.mjs --check  # 只做编译与语法校验，不写文件
node tests/smoke.cjs    # 加载构建产物跑冒烟测试（等价于 npm test）
```

构建本身会跑一组**打包器守卫自检**：循环依赖必须被拒绝（含 A→B→A 与自引用）、多声明符导出必须收集到全部名字、解构导出/`export {}`/`export default` 必须报错、Host 半边必须保留 `export function apply`。守卫失效会直接让构建失败，而不是留到浏览器里变成 `Maximum call stack size exceeded`。

冒烟测试用最小 DOM 桩 + 迷你 React（带按实例的 hooks）真实执行构建产物，覆盖：工厂注册、`apply` 注册两个插槽、六个标签页渲染、上传壁纸、开启壁纸后写入令牌覆盖表、六种特效逐帧绘制、裁切器打开、快捷面板打开、`destroy()` 清理。

## 已知限制

- **尚未在真实浏览器里目视验证**：本机没有可用的浏览器自动化，因此视觉效果（壁纸观感、模糊程度、面板透出比例）只经过逻辑级验证；装好后建议先调「界面透出」的滑块找手感。
- 面板模糊依赖几何采样，若某个面板采样失败则该面板只有透明、没有背后模糊（其余功能不受影响）。采样点按窗口比例计算，极小窗口下可能采不到输入框。
- 覆盖 `--dsw-alias-bg-base` 会让所有使用该令牌的小控件一起变得半透明，这是「让内容区透出壁纸」的代价；可用「整体压暗」与霜面模糊补偿可读性。

## 修复记录

- **v1.0.7**
  - 新增：高级页「默认值」卡片 —— **「把当前设置设为默认值」** 一键把屏幕上这套设置存成默认值（存进浏览器本地，独立于当前设置），此后「清除全部壁纸与设置」以及未来版本新增字段的回退值都会用它；「恢复出厂默认值」可撤销。卡片里还有一段只读 JSON，方便把这套默认值带到别的机器。
  - 出厂默认值已按你当前这套数值固化：不压暗、亮度/饱和度拉满、缩放 2×、缓慢推拉 36/2×、不叠加特效、轮播 120 秒、视频声音开启（音量 100%）。侧边栏/内容区/输入框/菜单的透出比例维持 62/48/70/76。
  - 说明：这套数值是我从应用浏览器的 IndexedDB 里恢复出来的（`studio-state` 记录），因此与你现在看到的一致；若之后又调过，点一下上面的按钮即可重新固化。
- **v1.0.6**
  - 修复：**动态特效完全不出画面**。特效画布的尺寸是从它自己的盒子量的，而这段测量只在 `window.resize` 时执行过——插件从没在「启动」和「图层由隐藏变可见」这两个时刻量过。图层在关闭时是 `display:none`，画布尺寸因此一直是 **0×0**，`draw()` 每帧第一件事就是发现宽高为 0 然后直接返回，于是任何特效都画不出来（换个窗口大小就会突然正常，这也解释了它为什么看起来时好时坏）。现在启动时、以及每次图层转为可见时都会测量画布。
  - 改进：系统开启「减少动态效果」时，特效页会**明确说明动效被暂停**并给一个「仍然播放动效」的按钮，而不是让滑块和特效看起来像坏了一样。
  - 新增：高级页诊断增加**特效一行**——特效名、画布实际像素尺寸、运行中 / 已暂停 / 未启动、是否被「减少动态效果」抑制。画布显示 `0×0` 就是本条 bug 的直接特征。
  - 测试：无头测试台把 `requestAnimationFrame` / `cancelAnimationFrame` 改成真实记账（原来 cancel 是空实现，导致「切换特效不得叠加动画循环」这条断言其实测不出问题），并新增断言：**特效画布必须被量到尺寸、并且真的产生绘制调用**——这条在上一版会当场失败。
- **v1.0.5**
  - 修复：**内容区与输入框的「背后模糊」失效**。霜面模糊是「几何采样定位面板 → 在插件图层画等位矩形」，而旧规则在颜色匹配不上时**取最小候选**：输入卡片里的小控件、消息气泡、甚至整窗框架都可能被选中，矩形要么小到看不出、要么干脆被丢弃，滑块就像死的一样。新规则三条：① 跨满整窗的候选一律当框架剔除（仅当没有其它候选时才退回使用）；② 侧边栏仍限制宽度不超过窗口 1/3；③ 在「真正画着该面板令牌」的候选里取**最外层**——面板容器本身，而不是里面的 chip / 行 / 气泡；只有全部对不上颜色时才退化为取最大候选。侧边栏因此从内层容器升级为整列（240px），内容区稳定落在对话区、输入框稳定落在输入卡片上。
  - 新增：高级页增加**「霜面实测」**一行，直接列出三个面板测到的矩形尺寸；显示 `—` 就代表该面板没测到，模糊自然无效。
  - 测试：无头测试台补了**贴近真实布局的几何仿真**（框架 / 侧边栏列 / 对话区 / 输入卡片，外加叠在上面的小控件与输入行），断言三个霜面矩形分别落在 240×900、1200×900、880×120 上。这条用例在上一版会当场失败，正是本次问题的复现。
- **v1.0.4**
  - 修复：v1.0.3 把侧边栏令牌设成 `transparent`、改由插件图层画填充，结果**探测选错了元素**：侧边栏自身变透明后颜色匹配失效，回退逻辑挑中了**整窗框架**，于是「侧边栏」的霜面矩形盖住整个窗口——滑块一动，模糊与着色就一起落到内容区。现在侧边栏令牌重新带上自己的透明度（能被我方匹配认出），框架改为**单独在元素上清底色**（`background-color` 只影响绘制，不会像 `backdrop-filter` 那样挪动 fixed 子元素），并加 `#root > :first-child` 的 CSS 兜底；侧边栏探测另加「宽度不得超过窗口 33%」的硬约束，框架不可能再被当成侧边栏。
  - 修复：所有探测改为在**关闭插件自身覆盖**的状态下进行（临时禁用覆盖表 + 摘掉内联声明，探完立刻还原）。否则第二轮起每个面板都画着插件写入的半透明色，唯独框架还是不透明，匹配必然挑错。顺带修掉一个真 bug：还原时误把「插件写入前的空值」写回，等于删掉了内联覆盖。
  - 修复：**菜单与弹层滑块看着没反应**。现在除了菜单材质，还覆盖下拉选择器与对话框 / 卡片所在层级（`--dsw-alias-bg-layer-2` / `-1`），所以拖动时**设置面板本身**就会变，不必先关设置再去开菜单对比。
  - 新增：高级页显示**当前版本号**（构建时从 `package.json` 注入），一眼确认页面里跑的是哪一版。
  - 修复：切换明暗主题时令牌颜色缓存未失效，深色主题会沿用浅色主题算出的颜色。
- **v1.0.3**
  - 修复：**「界面透出」里调侧边栏的不透明度会改到所有面板**。根因是 `--dsw-specific-sidebar-fill` 并非侧边栏私有：在带自绘标题栏的窗口上，整个应用框架（`.frame`）也用它当底色，因此按面板透明度覆盖这个令牌等于改了整窗底色。现在侧边栏令牌固定为 `transparent`（它同时清掉框架底色，壁纸才透得出来），侧边栏自己的填充改由插件图层绘制、只覆盖侧边栏矩形；侧边栏滑块不再影响内容区 / 输入框 / 菜单。侧边栏关闭「透出壁纸」时，矩形按 100% 不透明度绘制，看起来与原生侧边栏一致。
  - 修复：**菜单与弹层的透明度 / 模糊完全没有作用**。原因有两个：菜单面板默认是关闭的（滑块是灰的），以及菜单真正的材质令牌是 `--dsw-specific-menu` + `--dsw-menu-surface-fill` + `--dsw-menu-backdrop-filter`，此前一个都没覆盖到。现在菜单默认开启（不透明度 76%），两个填充令牌与模糊令牌都会被覆盖，滑块即时生效；旧版本保存的设置会在加载时自动迁移（`schemaVersion` 1 → 2）。
  - 测试：新增两条回归断言——「侧边栏滑块不得改动任何其他面板的令牌」与「菜单表面必须覆盖菜单材质三件套」，防止这两个问题回归。
- **v1.0.1**
  - 修复：启用壁纸后界面错位。原因是把 `backdrop-filter` 施加在宿主面板上，使面板成为其 `position: fixed` 子元素的包含块（桌面标题栏的品牌行、输入框浮动控件因此偏移）。现在改为在插件自己的图层内绘制霜面矩形，宿主元素零改动。已用真实浏览器逐元素几何比对验证：开/关壁纸时 308 个宿主元素坐标完全一致。
  - 修复：任何文件上传都提示"不支持"。`store.ts` 的 `tx()` 把 `const transaction` 声明在 `try` 块内、却在块外使用，运行时抛 `ReferenceError: transaction is not defined`，导致上传、保存设置、读取设置全部失败，而错误被笼统地报成"文件类型不支持"。
  - 改进：上传改为**先探测再判定**（由 Chromium 决定能否解码，而不是插件自己的 MIME 白名单），失败提示会带上文件名与真实原因（无法解码 / 存储不可用 / 文件过大）。
  - 测试：无头测试台补上 IndexedDB 与对象 URL 建模（原来 `indexedDB` 为空，正好绕过了出问题的那段代码），并新增"宿主元素不被改写"的不变量断言。
